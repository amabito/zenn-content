# 結論から言う

**マルチカメラで3DGSを学習する場合、フォトメトリック補正なしでは品質が大幅に劣化する。** 4つの主要手法（ExposureMLP、Appearance Embedding、Bilateral Grid、PPISP）を実装難易度・品質・汎化性能で比較した結果、用途に応じた最適解が明確になった。

4カメラ構成（Eagle LiDARスキャナ）で3DGS学習を行った実体験をベースに、補正なし/ありの品質差と、各手法の特徴を解説する。

**この記事で得られること:**
- マルチカメラ3DGSで発生するフォトメトリック不一致の原因
- 4つの補正手法の仕組み・長所・短所
- 用途別の手法選定ガイド

**対象読者:**
- 3DGSで実世界シーンを再構成している人
- マルチカメラ撮影で色ずれ・floater問題に悩んでいる人
- gsplat/nerfstudioの補正オプションを検討している人

# フォトメトリック不一致とは何か

## マルチカメラ3DGSの根本問題

3DGS学習では「同一3D点は同一色」を仮定する。しかし、現実のマルチカメラ構成ではこの仮定が成り立たない。

**不一致の4つの原因:**

| 原因 | 説明 | 影響 |
|------|------|------|
| **露出差** | カメラごとにオート露出が独立動作 | 同一面の明るさが矛盾 |
| **ビネッティング** | レンズの周辺光量落ち | 画像端が暗くなる度合いがカメラごとに異なる |
| **色収差** | ホワイトバランスの差 | 暖色/寒色の偏りがカメラ間で異なる |
| **CRF差** | ISPのトーンマッピング差 | ガンマカーブがカメラごとに異なる |

## 3DGS学習への影響

補正なしで学習すると以下の問題が発生する。

```
症状と原因:
├── floater（浮遊アーティファクト）
│   └── 原因: 色の矛盾を「別の面」として学習
├── ぼやけた再構成
│   └── 原因: 同一点の輝度不一致でGaussianが拡大
├── 色むら・色境界
│   └── 原因: カメラ境界で色が不連続
└── 新規視点での破綻
    └── 原因: per-view補正が新規視点で使えない
```

**定量的影響（筆者の実測）:**
- 補正なし: PSNR 22-24 dB
- 補正あり: PSNR 27-30 dB
- **差: 3-8 dB（目視でも明確に差がわかるレベル）**

# 手法1: ExposureMLP（アフィン変換）

## 概要

最もシンプルな補正手法。各画像に対してアフィン変換（スケール + バイアス）を適用する。

```
補正式: corrected = A * rgb + b
A: 3x3行列（チャネル間のクロス補正）
b: 3次元バイアスベクトル
```

## 特徴

| 項目 | 評価 |
|------|------|
| 実装難易度 | 低（数十行で実装可能） |
| 学習パラメータ数 | 12/画像（3x3 + 3） |
| 品質改善 | 中（露出差に有効） |
| 空間依存補正 | 不可（画像全体に均一） |
| 新規視点汎化 | 不可（per-viewパラメータ） |
| 採用例 | gsplatデフォルト |

## 長所

- **実装が極めて簡単:** gsplatには組み込み済み
- **学習が安定:** パラメータ数が少なく過学習しにくい
- **計算コストほぼゼロ:** 行列乗算1回
- **露出差の補正に十分:** 単一カメラの動画なら大半のケースをカバー

## 短所

- **ビネッティング補正不可:** 空間的に一様な変換しかできない
- **CRFの非線形性を捉えられない:** ガンマカーブはアフィンでは近似困難
- **新規視点で使えない:** テスト時にper-viewパラメータが存在しない

## 適用場面

```
推奨: 単一カメラの動画撮影、露出差が主な問題のケース
非推奨: マルチカメラリグ、ビネッティングが顕著なレンズ
```

# 手法2: Appearance Embedding（GLO）

## 概要

各画像にlatent vector（潜在ベクトル）を割り当て、デコーダで色補正を行う。Global Latent Optimization（GLO）とも呼ばれる。

```
処理フロー:
1. 画像iに対応するembedding e_i を取得（学習可能）
2. rgb_raw + e_i をデコーダに入力
3. デコーダが補正後のrgbを出力
```

## 特徴

| 項目 | 評価 |
|------|------|
| 実装難易度 | 中 |
| 学習パラメータ数 | embedding_dim x 画像数 + デコーダ |
| 品質改善 | 高（柔軟な補正が可能） |
| 空間依存補正 | デコーダ設計による |
| 新規視点汎化 | 弱（embeddingが存在しない） |
| 採用例 | NeRF-W、Nerfacto |

## 長所

- **表現力が高い:** 非線形な補正も学習可能
- **複雑な色変動に対応:** 照明変動、影、反射の違い
- **実績豊富:** NeRF-Wで提案され、広く採用

## 短所

- **過学習リスク:** embeddingがシーンの外観変動だけでなくジオメトリ情報も吸収
- **画像数に比例するパラメータ:** 大規模データセットでメモリ圧迫
- **新規視点への汎化が弱い:** テスト時のembeddingをどう設定するか問題
  - 平均embeddingを使う → 中途半端な補正
  - 最近傍のembeddingを使う → 不連続な遷移

## 適用場面

```
推奨: 照明条件が大きく変動するシーン、インターネット写真コレクション
非推奨: リアルタイム推論、新規視点レンダリング品質が重要なケース
```

# 手法3: Bilateral Grid（SIGGRAPH 2024）

## 概要

SIGGRAPH/TOG 2024で発表された手法。ISPの効果をlocally-affineなbilateral gridで近似する。

```
Bilateral Grid:
├── 3D格子（x, y, luminance）上にアフィン変換パラメータを格納
├── 各ピクセルの座標と輝度値で格子を補間
├── ピクセルごとに異なるアフィン変換を適用
└── データ駆動で学習
```

## 特徴

| 項目 | 評価 |
|------|------|
| 実装難易度 | 高 |
| 学習パラメータ数 | grid_resolution^3 x 12 / 画像 |
| 品質改善 | 高（局所的な補正が可能） |
| 空間依存補正 | 可能（bilateral gridの本質） |
| 新規視点汎化 | 弱（per-viewグリッドが必要） |
| 採用例 | ZipNeRF拡張 |

## 長所

- **空間的に異なる補正:** ビネッティングのような位置依存の補正が可能
- **輝度依存の補正:** 暗部と明部で異なる補正を適用
- **ユーザー編集との親和性:** 後処理としてのトーン調整も可能

## 短所

- **実装が複雑:** bilateral gridのCUDA実装が必要
- **メモリ消費:** 高解像度グリッドはGPUメモリを圧迫
- **新規視点への汎化:** per-viewグリッドが必要で、テスト時の対応が課題
- **ZipNeRF依存:** 原論文はZipNeRFベース、3DGSへの移植は追加作業

## 適用場面

```
推奨: 高品質な静的シーン再構成、後処理トーン編集が必要なケース
非推奨: リアルタイム推論、メモリ制約が厳しい環境
```

# 手法4: PPISP（NVIDIA, 2026年1月）

## 概要

NVIDIAが2026年1月に公開。ISPパイプラインを物理的に分解し、4つのモジュールで個別にモデル化する。Apache 2.0ライセンス。

```
4つの物理モジュール:
├── Exposure Compensation (per-frame) → 明るさ変動
├── Vignetting (per-camera)           → 周辺光量落ち
├── Color Correction (per-frame)      → 色かぶり
└── Camera Response Function (per-camera) → トーンマッピング
```

## 特徴

| 項目 | 評価 |
|------|------|
| 実装難易度 | 中（pip installで導入可能） |
| 学習パラメータ数 | カメラ数依存（画像数ではない） |
| 品質改善 | 最高（物理ベースの分解） |
| 空間依存補正 | 可能（ビネッティングモジュール） |
| 新規視点汎化 | 強（コントローラによる自動予測） |
| 採用例 | gsplat/3DGRUT統合予定 |

## 長所

- **物理的解釈可能:** 各パラメータがISPの物理量に対応
- **per-cameraとper-frameの分離:** ビネッティング・CRFはカメラ固有、露出・色補正はフレーム固有
- **新規視点への汎化:** コントローラネットワークがper-frameパラメータを予測
- **スケーラブル:** パラメータ数が画像数でなくカメラ数に比例
- **Apache 2.0:** 商用利用可能

## 短所

- **2段階学習が必要:** Stage 1（共同最適化）+ Stage 2（コントローラ蒸留）
- **新しい手法:** 2026年1月公開のため実績が少ない
- **CUDAビルドが必要:** pip installにCUDAコンパイル環境が必要

## 適用場面

```
推奨: マルチカメラリグ、動画からの3DGS、新規視点品質が重要なケース
非推奨: 単一カメラ・短時間撮影（オーバースペック）
```

# 4手法の総合比較

## 比較表

| 観点 | ExposureMLP | Appearance Embedding | Bilateral Grid | PPISP |
|------|-------------|---------------------|----------------|-------|
| **実装難易度** | 低 | 中 | 高 | 中 |
| **品質改善** | 中 | 高 | 高 | 最高 |
| **空間依存** | 不可 | 設計依存 | 可能 | 可能 |
| **新規視点** | 不可 | 弱 | 弱 | 強 |
| **計算コスト** | 極小 | 小 | 中 | 小 |
| **物理解釈** | 部分的 | なし | なし | あり |
| **ライセンス** | OSS内蔵 | OSS | 論文実装 | Apache 2.0 |

## 用途別推奨

| ユースケース | 推奨手法 | 理由 |
|------------|---------|------|
| **単一カメラ動画** | ExposureMLP | 十分な品質、実装コスト最小 |
| **インターネット写真** | Appearance Embedding | 照明変動の大きいデータに強い |
| **高品質静的再構成** | Bilateral Grid | 局所補正による高品質 |
| **マルチカメラリグ** | PPISP | 物理分解 + 新規視点汎化 |
| **自動運転データ** | PPISP | 多カメラ + 動画に最適 |
| **ドローン撮影** | ExposureMLP or PPISP | 照明変動の程度による |

# 実体験：4カメラ構成での品質劣化

## 問題の発生

Eagle（LiDAR + 4カメラ）で撮影したデータを3DGS学習にかけた際、以下の問題が発生した。

```
観察された症状:
├── カメラ境界に明確な色の段差
├── floaterが大量発生（特にカメラ切り替わり領域）
├── PSNR: 22.1 dB（期待値より5 dB以上低い）
└── 天井や壁面にゴースト状のアーティファクト
```

## ExposureMLPによる対処

まずExposureMLPを適用した。

```
結果:
├── PSNR: 22.1 → 25.8 dB（+3.7 dB）
├── floater: 大幅減少
├── 色の段差: 軽減されたが完全には解消せず
└── ビネッティング: 補正できず（画像端が暗いまま）
```

**ExposureMLPの限界を体感した。** 露出差の補正には効果的だが、ビネッティングやCRF差には対応できない。

## 物理ベースアプローチへの注目

PPISPの物理分解アプローチは、筆者が直面した問題に対する根本的な解決策を提供する。

```
PPISPで期待される改善:
├── Vignettingモジュール → 周辺光量落ちの補正
├── CRFモジュール → カメラごとのトーンマッピング差を吸収
├── コントローラ → 新規視点での自動補正
└── 学習パラメータ → カメラ4台分のみ（画像数非依存）
```

# まとめ

| 項目 | 詳細 |
|------|------|
| **問題** | マルチカメラ3DGSの色不一致 |
| **原因** | 露出差・ビネッティング・色収差・CRF差 |
| **簡易対策** | ExposureMLP（実装5分、効果中） |
| **本格対策** | PPISP（物理分解、新規視点汎化あり） |
| **品質差** | 補正なし vs ありで3-8 dB差 |

**フォトメトリック補正は3DGS品質の「最後の数dB」を決める。** 特にマルチカメラ構成では、補正なしの学習は品質を無駄にしている。ExposureMLPから始めて、必要に応じてPPISPに移行するのが現実的なアプローチだ。
