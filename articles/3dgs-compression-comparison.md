# 結論から言う

**3DGSモデルは圧縮技術で1/10〜1/100にできる。**

| 手法 | 圧縮率 | 品質低下 | 用途 |
|------|--------|---------|------|
| Pruning | 3-10倍 | 小 | 基本対策 |
| 量子化 | 5-20倍 | 中 | 配信向け |
| コーデック | 10-100倍 | 大 | ストリーミング |

この記事では、各圧縮手法の特徴と選び方を解説する。

---

# なぜ圧縮が必要か

## 3DGSのファイルサイズ

```
典型的なシーン:
├── Gaussian数: 100万〜500万
├── 1 Gaussianあたり: 約60バイト
│   ├── 位置 (xyz): 12バイト
│   ├── スケール (xyz): 12バイト
│   ├── 回転 (quaternion): 16バイト
│   ├── 不透明度: 4バイト
│   └── 色 (SH係数): 48バイト〜
├── 合計: 60MB〜500MB
└── 問題: Webで配信するには大きすぎる
```

## 配信の現実

```
ユーザー体験:
├── 100MB: モバイルで30秒待ち → 離脱
├── 10MB: 3秒で読み込み → 許容範囲
├── 1MB: 即座に表示 → 快適

目標:
├── Web配信: 10MB以下
├── モバイル: 5MB以下
└── ストリーミング: 1MB/秒以下
```

---

# 圧縮手法1: Pruning（枝刈り）

## 概念

```
Pruning:
├── 重要度の低いGaussianを削除
├── 可視性が低い → 削除
├── 他とほぼ重複 → 削除
├── 画質への寄与が小さい → 削除
└── 結果: Gaussian数を減らしてサイズ削減
```

## 効果

| 削減率 | 品質(PSNR) | 用途 |
|--------|-----------|------|
| 50% | -0.5 dB | ほぼ劣化なし |
| 70% | -1.0 dB | 軽微な劣化 |
| 90% | -3.0 dB | 目視でわかる |

## 適用シーン

```
向いているケース:
├── 冗長なGaussianが多いシーン
├── 品質より速度を優先
├── LOD（詳細度レベル）用の低品質版

向いていないケース:
├── 既に最適化済みのモデル
├── 細部が重要なシーン
└── 品質を最優先する用途
```

---

# 圧縮手法2: 量子化

## 概念

```
量子化:
├── 浮動小数点 → 整数に変換
├── 32bit float → 16bit / 8bit
├── 精度は下がるがサイズ大幅削減
└── GPU対応フォーマットあり
```

## 各属性の量子化

| 属性 | 元 | 量子化後 | 削減率 |
|------|-----|---------|--------|
| 位置 | FP32 | FP16 | 50% |
| スケール | FP32 | FP16 | 50% |
| 回転 | FP32 | INT8 | 75% |
| 不透明度 | FP32 | INT8 | 75% |
| 色(SH) | FP32 | INT8 | 75% |

## 総合効果

```
FP32 (60バイト/Gaussian)
↓ 全属性FP16
FP16 (30バイト/Gaussian) → 2倍圧縮
↓ 色・回転をINT8
混合量子化 (20バイト/Gaussian) → 3倍圧縮
↓ 高度な量子化（クラスタリング等）
5-10バイト/Gaussian → 6-12倍圧縮
```

---

# 圧縮手法3: コーデック

## 概念

```
コーデック:
├── 動画圧縮の概念を3DGSに適用
├── フレーム間予測（動的シーン）
├── エントロピー符号化
├── 辞書ベース圧縮
└── 最高の圧縮率だが複雑
```

## 代表的な手法

| 手法 | 圧縮率 | 特徴 |
|------|--------|------|
| gzip（汎用） | 2-3倍 | 簡単、どこでも使える |
| 専用コーデック | 10-50倍 | 高圧縮、デコーダ必要 |
| ストリーミング対応 | 20-100倍 | 動的LOD、帯域適応 |

## 適用シーン

```
向いているケース:
├── 大規模シーンの配信
├── ストリーミング再生
├── 帯域制限のある環境

向いていないケース:
├── リアルタイム編集
├── 高品質が必須
└── 実装コストを抑えたい
```

# 手法の組み合わせ

## 段階的な圧縮パイプライン

```
元モデル (500MB)
    │
    ▼ [1] Pruning（80%削減）
軽量モデル (100MB)
    │
    ▼ [2] 量子化（4倍圧縮）
量子化モデル (25MB)
    │
    ▼ [3] gzip（2倍圧縮）
配信モデル (12MB)
    │
    ▼ [4] 専用コーデック（5倍圧縮）
ストリーミング (2.5MB)
```

## 用途別推奨

| 用途 | 推奨手法 | 目標サイズ |
|------|---------|-----------|
| デスクトップアプリ | Pruning + 量子化 | 50MB |
| Webビューア | 全手法 | 10MB |
| モバイルアプリ | 全手法 + LOD | 5MB |
| ストリーミング | コーデック | 1MB/秒 |

# 品質評価指標

## PSNR（ピーク信号対雑音比）

```
PSNR:
├── 30 dB未満: 劣化が目立つ
├── 30-35 dB: 許容範囲
├── 35-40 dB: 高品質
└── 40 dB以上: ほぼ原画質
```

## SSIM（構造的類似度）

```
SSIM:
├── 0.9未満: 劣化が目立つ
├── 0.9-0.95: 許容範囲
├── 0.95-0.99: 高品質
└── 0.99以上: ほぼ同一
```

## 主観評価

```
最終的には人間の目で確認:
├── 重要な部分の劣化がないか
├── アーティファクトが目立たないか
├── 実用上問題ないか
└── 数値だけで判断しない
```

# 実装時の注意点

## 1. 可逆性を確保

```
推奨:
├── 元モデルは必ず保存
├── 圧縮は配信用のコピーに適用
├── 再圧縮が必要になる場合に備える
```

## 2. 段階的に適用

```
推奨:
├── 一気に圧縮せず段階的に
├── 各段階で品質確認
├── 問題があれば前段階に戻る
```

## 3. ターゲット環境でテスト

```
推奨:
├── 開発環境だけでなく実機でテスト
├── モバイルでの表示確認
├── 低帯域でのストリーミングテスト
```

# まとめ

| 手法 | 圧縮率 | 品質影響 | 実装難度 |
|------|--------|---------|----------|
| Pruning | 3-10倍 | 小 | 低 |
| 量子化 | 5-20倍 | 中 | 中 |
| コーデック | 10-100倍 | 大 | 高 |

**推奨アプローチ:**
1. まずPruningで不要なGaussianを削除
2. 量子化でサイズ削減
3. 必要に応じてコーデック適用

**目標: 品質を保ちつつ、配信可能なサイズに。**
