# 結論から言う

**レガシー業界のDXは、99%が失敗する。理由は「技術」ではなく「人」にある。**

建設コンサルタントとして10年、数十社のDX支援に関わった。成功したのは数社。残りは「導入したけど使われない」「現場が反発」「予算オーバー」で頓挫した。

この記事では、レガシー業界でDXを成功させるための5つの原則を解説する。

- 具体的な進め方

# なぜDXは失敗するのか

## 典型的な失敗パターン

```
経営層: 「DXやるぞ！最新システム入れろ！」
     ↓
情シス: 「高機能なシステムを導入しました」
     ↓
現場: 「使い方わからん」「今のやり方で十分」
     ↓
1年後: 誰も使っていないシステムが残る
```

## 失敗の根本原因

| 原因 | 割合 | 内容 |
|------|------|------|
| 現場の反発 | 40% | 「今のままでいい」 |
| 経営の理解不足 | 25% | 「入れれば何とかなる」 |
| 技術選定ミス | 20% | オーバースペック or 使いにくい |
| 予算・体制不足 | 15% | 途中で息切れ |

**技術の問題は20%だけ。80%は「人」の問題。**

---

# 原則1: 「最小の変化」から始める

## ❌ 失敗例

```
「基幹システムを全面刷新！」
「紙を全廃してペーパーレス化！」
「AIで業務を自動化！」

→ 現場がパニック → 反発 → 頓挫
```

## ✅ 成功例

```
「この1つの帳票だけExcel化しませんか？」
「この会議だけオンラインにしませんか？」
「この1人だけ新しいツール使ってみませんか？」

→ 小さな成功 → 「便利じゃん」 → 横展開
```

## 具体的なアプローチ

```
Step 1: 最も不満が大きい業務を1つ選ぶ
Step 2: 影響範囲が小さい改善から始める
Step 3: 成功したら隣の業務に横展開
Step 4: 繰り返し
```

**「革命」ではなく「進化」を狙う。**

---

# 原則2: 「現場のエース」を味方にする

## 組織の力学

```
経営層: 「DXやれ」（権限はあるが現場を知らない）
中間管理職: 「面倒...」（現状維持バイアス）
現場: 「また新しいこと？」（拒否反応）

→ 誰も本気で動かない
```

## キーパーソン戦略

```
現場のエース（ベテラン、信頼されている人）
  ↓
この人が「いいね」と言えば周りも動く
  ↓
最初にこの人を巻き込む
```

## 巻き込み方

```
❌ 「新しいシステム使ってください」
✅ 「〇〇さんの意見を聞かせてください」
✅ 「〇〇さんなら、どう改善しますか？」
✅ 「〇〇さんに試してもらえませんか？」

→ 「自分のアイデア」にする
```

**押し付けではなく、巻き込み。**

# 原則3: 「成果」を見せ続ける

## よくある失敗

```
4月: DXプロジェクト開始！
5月: システム選定中...
6月: 開発中...
7月: テスト中...
8月: 経営層「いつ効果出るの？」
9月: 予算カット
```

## 成功パターン

```
4月: DXプロジェクト開始！
5月: 小さな改善を1つ実施 → 効果報告「月10時間削減」
6月: 次の改善を実施 → 効果報告「エラー50%減」
7月: 次の改善を実施 → 効果報告「顧客満足度向上」
8月: 経営層「いいね、続けて」
9月: 予算追加
```

## 効果の見せ方

```
Before/After を数字で示す:
- 作業時間: 8時間 → 2時間（75%削減）
- ミス件数: 月10件 → 月2件（80%減）
- 残業時間: 月40時間 → 月20時間（50%減）
```

**小さな成果を積み重ねる。**

# 原則4: 「逃げ道」を用意する

## レガシー業界の現実

```
「システムが止まったらどうする？」
「紙がないと不安」
「前のやり方に戻せる？」

→ この不安に答えられないとDXは進まない
```

## 逃げ道の設計

```
✅ 並行運用期間を設ける
「3ヶ月は紙とシステム両方で運用します」

✅ ロールバック手順を明確に
「いつでも前のやり方に戻せます」

✅ サポート体制を明示
「困ったら〇〇さんに聞いてください」
```

## 移行の段階

```
Phase 1: 新旧並行（安心感）
Phase 2: 新メイン、旧バックアップ
Phase 3: 新のみ（旧は緊急用）
Phase 4: 旧を廃止

各フェーズで「問題があれば戻せる」を担保
```

**安心感がないと、人は動かない。**

# 原則5: 「ITリテラシー」を前提にしない

## 現実

```
建設業の現場:
- 平均年齢50代
- スマホは使えるがPCは苦手
- 「ログイン」「パスワード」でつまずく
```

## 失敗する導入

```
情シス: 「マニュアル読んでください」
現場: 「読んでもわからん」
情シス: 「研修やります（1回だけ）」
現場: 「忘れた」
```

## 成功する導入

```
✅ 操作を極限まで簡単にする
→ ボタン3つ以内で完結

✅ 「ITに詳しくない人」でテストする
→ 60代のベテランに使ってもらう

✅ サポート担当を現場に置く
→ 「わからなかったら〇〇さんに聞いて」

✅ 動画マニュアルを作る
→ 文字より動画
```

**「説明しなくても使える」が理想。**

# 具体的な進め方

## ステップ1: 現状把握（1-2週間）

```
- 現場をヒアリング
- 最も不満が大きい業務を特定
- キーパーソンを見つける
```

## ステップ2: 最小の改善を実施（2-4週間）

```
- 1つの業務、1つのツール
- キーパーソンと一緒に進める
- 効果を測定
```

## ステップ3: 成果を共有（1週間）

```
- 経営層に報告
- 現場に「こんなに楽になった」を伝える
- 次の改善案を提案
```

## ステップ4: 横展開（繰り返し）

```
- 成功パターンを他の業務に適用
- 徐々に範囲を広げる
- 半年〜1年で大きな変化に
```

# 建設業での具体例

## 成功事例: 日報のデジタル化

```
Before:
- 手書き日報 → FAX → 事務が入力 → Excel集計
- 所要時間: 30分/人/日

After:
- スマホで写真撮って送信
- 自動で集計
- 所要時間: 5分/人/日

効果: 1人あたり月8時間削減
```

## 成功の要因

```
1. 最小の変化: 日報だけに絞った
2. キーパーソン: 現場監督のエースに協力依頼
3. 成果を見せる: 「月8時間削減」を数字で報告
4. 逃げ道: 最初は紙と並行運用
5. 簡単操作: 写真撮るだけ
```
