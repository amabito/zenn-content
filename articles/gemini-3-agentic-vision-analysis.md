# 結論から言う

**Gemini 3 FlashのAgentic Visionは、AIが画像を「見る」から「能動的に調査する」へ進化したことを示す。** 画像を拡大し、注目領域を指定し、Pythonコードを実行して境界ボックスを描画する。従来のVLM（Vision-Language Model）が1回の推論で答えを出していたのに対し、Agentic Visionは複数ステップで画像を「探索」する。

3DGS/Computer Vision開発者にとって、これは点群品質の自動診断やレンダリング評価の自動化に直結する技術だ。

**この記事で得られること:**
- Agentic Visionの技術的仕組みと従来VLMとの違い
- 3DGS/CV分野での具体的活用可能性
- Gemini 3 Pro/Flashの位置づけとAPI利用方法
- 開発者視点での評価と制限事項

**対象読者:**
- VLMの最新動向を追いかけている開発者
- Computer Vision/3DGSで品質評価を自動化したい人
- Gemini APIを活用した画像解析に興味がある人

# Agentic Visionとは何か

## 従来のVLMとの違い

従来のVLM（GPT-4V、Claude Vision、Gemini 1.5 Pro等）は、画像を1回の推論で処理する。

```
従来のVLM:
  画像 → [モデル推論 1回] → テキスト回答

Agentic Vision:
  画像 → [観察] → [拡大] → [領域指定] → [コード実行]
       → [結果確認] → [追加調査] → 最終回答
```

**本質的な違い:** Agentic Visionはモデル自身が「次に何を調べるか」を判断し、ツール（画像操作・コード実行）を使って段階的に画像を理解する。

## 具体的な動作フロー

Agentic Visionが画像中の小さな文字を読む場合の動作例:

```
Step 1: 画像全体を観察
  → "右下に小さなテキストがある"

Step 2: 右下領域を拡大（crop + resize）
  → 拡大画像を再度観察

Step 3: Pythonコードで境界ボックスを描画
  → テキスト領域を正確に特定

Step 4: 特定した領域をさらに拡大
  → テキストを読み取り

Step 5: 結果を統合して回答
  → "右下のテキストは '...' です"
```

**ポイント:** 人間が画像を調べるときの行動（全体を見る→気になる部分を拡大→詳しく見る）をAIが再現している。

# 技術的仕組み

## 3つの能力の組み合わせ

Agentic Visionは3つの能力を組み合わせて機能する。

| 能力 | 説明 | 従来VLMとの差 |
|------|------|-------------|
| **画像拡大・クロップ** | 任意の領域を拡大して再観察 | 従来は1解像度のみ |
| **領域指定** | bounding boxで注目領域を明示 | 従来はattentionに依存 |
| **コード実行** | Python/PILで画像処理を実行 | 従来はテキスト出力のみ |

## なぜ「能動的」が重要か

従来のVLMには解像度の壁がある。

```
従来VLMの制約:
├── 入力解像度に上限がある（例: 1024x1024）
├── 小さな物体・文字は潰れて認識不能
├── 全画像を等しい解像度で処理 → リソース非効率
└── 「見えない」ものについて幻覚を生成するリスク
```

Agentic Visionは必要な部分だけを拡大するため、高解像度画像の詳細を効率的に理解できる。

## Gemini 3のモデル構成

| モデル | 特徴 | Agentic Vision |
|--------|------|---------------|
| **Gemini 3 Flash** | 高速・低コスト | 対応 |
| **Gemini 3 Pro** | 高品質・推論重視 | 対応（より高精度） |
| Gemini 2.0 Flash | 前世代 | 非対応 |

**Gemini 3 Flashが本命:** Agentic Visionはステップ数が多い（=トークン消費が多い）ため、低コストのFlashが実用的。

# 3DGS/Computer Vision分野での活用可能性

## 活用1: 点群品質の自動診断

SfM/COLMAPの出力点群の品質を画像から自動評価する。

```
ユースケース:
├── 入力: 点群の可視化画像（CloudCompare等からエクスポート）
├── Agentic Visionに依頼:
│   "この点群画像の品質問題を指摘してください"
├── AIの動作:
│   1. 全体を観察 → "左上に疎な領域がある"
│   2. 疎な領域を拡大 → "点群密度が不十分"
│   3. 色分布を確認 → "一部にアウトライアー（ノイズ点）"
│   4. 境界ボックスで問題領域をマーク
└── 出力: 問題領域のリスト + 改善提案
```

**従来のアプローチとの比較:**
- 手動: 目視で確認 → 時間がかかる、見落とし
- スクリプト: 密度計算 → 定量的だが文脈理解なし
- Agentic Vision: 視覚的 + 文脈理解 → 人間に近い診断

## 活用2: SfM結果の視覚的レビュー

COLMAPの再構成結果を自動レビューする。

```
確認項目:
├── カメラ配置の妥当性（全方位カバーされているか）
├── 再構成の完全性（欠落領域がないか）
├── スケール推定の妥当性
└── アウトライアーの検出
```

**実装アイデア:**
1. COLMAPのsparse reconstructionをMeshLab/CloudCompareでレンダリング
2. 複数角度からスクリーンショットを撮影
3. Gemini 3 Agentic Visionに品質レビューを依頼
4. 問題がある場合は撮影追加の提案を出力

## 活用3: レンダリング品質の定量・定性評価

3DGS学習結果のレンダリング画像を自動評価する。

```
評価可能な項目:
├── floater（浮遊アーティファクト）の検出と位置特定
├── ぼけ領域の特定
├── 色むら・色境界の検出
├── テクスチャの自然さの評価
├── 穴（背景が見える領域）の検出
└── GT画像との視覚的比較
```

**PSNR/SSIMとの違い:** 定量指標は数値を出すだけだが、Agentic Visionは「どこが」「なぜ」問題なのかを言語化できる。品質レポートの自動生成に使える。

## 活用4: HyperViewerとの連携可能性

HyperViewer（WebGPU 3DGSビューア）のレンダリング結果をGemini 3で自動評価するパイプライン。

```
連携フロー:
├── HyperViewerで複数視点からレンダリング
├── スクリーンショットをGemini 3 APIに送信
├── Agentic Visionが品質を評価
├── 問題領域をbounding boxで特定
└── 改善提案をレポートとして出力
```

**WebGPU + AI評価のメリット:**
- ブラウザ上で完結（サーバーサイド不要）
- 非エンジニアでも品質確認が可能
- CI/CDパイプラインに組み込み可能

# API利用方法

## Gemini 3 Flash APIの基本

```
API呼び出しの構造:
├── エンドポイント: generativelanguage.googleapis.com
├── モデル: gemini-3-flash
├── 入力: テキスト + 画像（Base64 or GCS URI）
├── Agentic Vision有効化: tools設定で指定
└── 出力: テキスト + 画像操作のトレース
```

## Agentic Visionの有効化

通常のVision APIとの違いは、ツール使用を有効にする点。

```
必要な設定:
├── code_execution: true（Pythonコード実行を許可）
├── image_tools: true（画像操作ツールを許可）
└── これにより、モデルが自発的に画像を拡大・加工する
```

## コスト見積もり

| 操作 | トークン消費 | 概算コスト |
|------|------------|-----------|
| 通常のVision（1回推論） | 1K-5K | $0.001-0.005 |
| Agentic Vision（3-5ステップ） | 5K-20K | $0.005-0.02 |
| Agentic Vision（10+ステップ） | 20K-50K | $0.02-0.05 |

**注意:** Agentic Visionはステップ数に比例してコストが増加する。バッチ処理ではFlashモデルを使い、重要な評価のみProを使うのがコスト効率的。

# 開発者視点での評価

## 強み

```
Agentic Visionの強み:
├── 高解像度画像の詳細理解
│   → 従来VLMの解像度制約を回避
├── 能動的な情報収集
│   → 必要な部分だけを深掘り
├── コード実行による精密な処理
│   → bounding box描画、ピクセル計算
├── 推論過程の透明性
│   → 各ステップが追跡可能
└── ワンショットでの多面的分析
    → 1枚の画像から複数の観点を自動チェック
```

## 制限事項

```
現時点の制限:
├── レイテンシ
│   → 複数ステップのため応答に5-30秒
│   → リアルタイム処理には不向き
├── コスト
│   → 1推論あたりのトークン消費が多い
│   → 大量画像のバッチ処理は高コスト
├── 確定性の欠如
│   → 同じ画像でも毎回異なるステップを踏む可能性
│   → 品質評価の再現性に課題
├── ツール実行の制約
│   → 使えるPythonライブラリに制限がある
│   → カスタムCV処理は組み込めない
└── ドメイン知識の深さ
    → 3DGS特有のアーティファクト（floater等）の認識精度は不明
    → プロンプトエンジニアリングでカバーする必要
```

## 他のVLMとの比較

| 観点 | GPT-4o | Claude Sonnet | Gemini 3 Flash |
|------|--------|--------------|----------------|
| 1回推論の品質 | 高 | 高 | 中-高 |
| 能動的探索 | 不可 | 不可 | **可能** |
| コード実行 | 可能（Code Interpreter） | 不可（API単体） | **画像操作可能** |
| コスト | 高 | 中 | 低 |
| 速度 | 中 | 中 | 高 |

**Agentic Visionのユニークな強み:** 画像を「見て、拡大して、コードで処理する」の一連のフローを自律的に行える点。GPT-4oのCode Interpreterは画像生成はできるが、画像の能動的な探索は行わない。

# 今後の展望

## VLMの進化方向

```
2025: 1回推論のVLM（GPT-4V, Claude Vision）
2026: Agentic Vision（Gemini 3）← 今ここ
2027?: マルチモーダルAgent（動画理解、3D理解、物理シミュレーション）
```

Agentic Visionは「VLMのAgent化」の第一歩。今後は動画の能動的な理解（特定フレームに戻って確認する等）や、3Dデータの直接理解が期待される。

## 3DGS分野への影響

```
短期（2026年）:
├── レンダリング品質の自動評価
├── 点群品質のスクリーニング
└── 品質レポートの自動生成

中期（2027年）:
├── 学習パラメータの自動チューニング
│   → 品質評価 → パラメータ調整 → 再学習のループ
├── 撮影計画の自動提案
│   → SfM結果を見て「ここの撮影を追加してください」
└── エンドツーエンドの品質管理パイプライン

長期（2028年以降）:
├── 3Dデータの直接理解
│   → 点群・メッシュを入力としてAIが分析
└── 3D生成との統合
    → AIが3DGSモデルの品質を評価しながら生成
```
