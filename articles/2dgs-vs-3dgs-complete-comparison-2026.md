## 導入：PSNR 28の壁

3D Gaussian Splatting（3DGS）で高品質な3D再構成を実現してきたが、ある時点で品質の限界にぶつかった。PSNR 28付近で頭打ちになり、いくらハイパーパラメータを調整してもそれ以上改善しない。

「もっと高品質な再構成は不可能なのか？」

調べると、**2D Gaussian Splatting（2DGS）** という選択肢があった。論文によれば、3DGSに対して+1〜3 dB PSNRの改善が得られるという。

しかし、筆者は自作の3DGSラスタライザー（HyperRasterizer）を開発しており、FP16最適化やSoAレイアウトなど様々な最適化を施してきた。2DGSに移行すると、これらの実装を**全面的に書き直す**必要がある。

果たして2DGSへの移行は本当に価値があるのか？どのような場合に2DGSを選ぶべきなのか？

本記事では、3DGSと2DGSの技術的な違いを実装者の視点で徹底比較し、2026年時点での判断基準を示す。

---

## 3DGSのおさらい：3D楕円体による表現

まず、3D Gaussian Splattingの基本を簡潔に復習する。

### 3DGSの仕組み

3DGSでは、シーンを**無数の3D楕円体（ellipsoid）** で表現する。各楕円体は以下のパラメータを持つ：

| パラメータ | 次元 | 説明 |
|-----------|------|------|
| 位置（position） | 3 | 3D空間上の中心座標 |
| スケール（scale） | 3 | X/Y/Z軸方向の広がり |
| 回転（rotation） | 4 | クォータニオンで表現 |
| 不透明度（opacity） | 1 | アルファ値 |
| SH係数 | 16〜48 | 視点依存色（球面調和関数） |

**合計：約27〜63パラメータ/Gaussian**

### レンダリングパイプライン

1. **投影**：3D楕円体を2Dスクリーン空間に射影
2. **ソート**：深度順にソート
3. **アルファブレンディング**：前から順に色を合成

```
3D Ellipsoid → 2D Projection → Alpha Blending
     ╱│╲             ╱─╲
    ╱ │ ╲           │   │
   ╱  │  ╲          ╰───╯
  3D空間          スクリーン
```

### 3DGSの長所

- **ボリューメトリック効果が得意**：煙、霧、半透明物体を自然に表現
- **訓練が安定**：densification（分裂）とpruning（削除）のバランスが取りやすい
- **成熟したエコシステム**：ビューア、エディタ、各種ツールが充実
- **実装が豊富**：PyTorch、CUDA、WebGPU版など多数

### 3DGSの弱点

- **サーフェス品質が低い**：楕円体に「厚み」があるため、エッジがぼやける
- **奥行き方向のブラー**：同じ視線上に複数の楕円体が重なるとぼける
- **メッシュ抽出の品質**：Poisson Reconstructionでもノイジーになりがち
- **PSNR上限**：データセットにもよるが28〜30 dB付近で頭打ち

この「サーフェス品質」と「奥行きブラー」の問題を解決するために登場したのが2DGSだ。

## 2DGSとは：厚みゼロの2Dディスク

2D Gaussian Splatting（2DGS）は、Huang et al. (2024)によって提案された手法で、3DGSの「3D楕円体」を**2Dディスク（surfel、surface element）** に置き換える。

### なぜ「2D」なのか？

重要なのは、「2D」という名前だが**3D空間に配置される**点だ。混乱を避けるために整理する：

- **3DGS**：3D空間に配置された3次元楕円体（XYZ軸すべてに広がりがある）
- **2DGS**：3D空間に配置された2次元ディスク（**奥行き方向の厚みがゼロ**）

つまり、2DGSの「2D」は「厚みがない平面要素」という意味であり、「2D画像」という意味ではない。

### 2Dディスクの構造

各ディスクは以下のパラメータを持つ：

| パラメータ | 次元 | 説明 |
|-----------|------|------|
| 位置（position） | 3 | 3D空間上の中心座標 |
| スケール（scale） | 2 | ディスクの半径（XY平面） |
| 法線（normal） | 3 | ディスクの向き |
| 不透明度（opacity） | 1 | アルファ値 |
| SH係数 | 16〜48 | 視点依存色 |

**合計：約25〜57パラメータ/Gaussian**

3DGSと比較して：

- **スケールが3→2次元**：奥行き方向のスケールが不要
- **回転→法線**：クォータニオン（4次元）から法線ベクトル（3次元）に変更
- **パラメータ総数はやや減少**

### レンダリング：レイ-ディスク交差判定

3DGSとの最大の違いは**レンダリング方法**だ。

**3DGS**：
```
カメラ → 3D楕円体を2D投影 → スクリーン上の楕円を描画
```

**2DGS**：
```
カメラ → ピクセルごとにレイを飛ばす → 各ディスクとの交差判定
```

2DGSでは、各ピクセルから視線（ray）を飛ばし、3D空間上のディスクとの交差点を計算する。これは**レイトレーシング的なアプローチ**に近い。

```
     Camera
       │
       │ Ray
       ▼
    ╭─────╮  ← 2D Disk (normal vector)
    │  ●  │
    ╰─────╯
   Intersection
```

### なぜPSNRが向上するのか

2DGSが3DGSより高品質な理由は**奥行き方向のブラー排除**にある。

**3DGSの問題**：
```
カメラ → ●●●●● ← 5個の楕円体が重なる
         ↑
    奥行き方向に厚みがある
    → 全部がアルファブレンドされる
    → ぼやける
```

**2DGSの解決**：
```
カメラ → │ │ │ ← 3枚のディスク（厚みゼロ）
         ↑
    レイと交差した1枚だけヒット
    → シャープな境界
```

ディスクは厚みがゼロなので、視線上で「最も近いディスク1枚」だけが選ばれる（または複数枚と交差しても、交差点が明確に分離される）。これにより、**エッジがシャープ**になり、PSNRが+1〜3 dB向上する。

## パラメータ比較：3DGS vs 2DGS

両者のパラメータ構造を表で整理する。

| 項目 | 3DGS | 2DGS |
|------|------|------|
| **形状** | 3D楕円体 | 2Dディスク（surfel） |
| **位置** | (x, y, z) | (x, y, z) |
| **スケール** | (sx, sy, sz) 3軸 | (sx, sy) 2軸のみ |
| **向き** | クォータニオン (qw, qx, qy, qz) | 法線ベクトル (nx, ny, nz) |
| **不透明度** | α | α |
| **色** | SH係数（16〜48次元） | SH係数（16〜48次元） |
| **合計次元** | 27〜63 | 25〜57 |
| **厚み** | あり（奥行き方向に広がる） | なし（厚みゼロ） |
| **法線の明示性** | なし（暗黙的） | あり（明示的） |

### 重要な違い：法線ベクトルの存在

2DGSでは**法線ベクトルが明示的**に存在する。これは以下の用途で重要：

1. **リライティング**：法線があるため、照明モデル（PBR等）を適用しやすい
2. **メッシュ抽出**：Poisson Reconstructionで法線を直接使える
3. **物理シミュレーション**：サーフェスの向きが明確

3DGSでは法線は暗黙的（楕円体の形状から推定）なので、これらの用途では精度が落ちる。

Huang et al. (2024)の論文から、代表的なデータセットでのPSNR比較を示す。

| シーン | 3DGS | 2DGS | 改善 |
|--------|------|------|------|
| Garden | 27.4 dB | 29.9 dB | **+2.5 dB** |
| Bicycle | 25.2 dB | 27.8 dB | **+2.6 dB** |
| Bonsai | 32.0 dB | 33.5 dB | **+1.5 dB** |
| Counter | 29.0 dB | 30.2 dB | **+1.2 dB** |
| Kitchen | 31.3 dB | 32.6 dB | **+1.3 dB** |
| Room | 31.6 dB | 32.9 dB | **+1.3 dB** |
| Stump | 26.6 dB | 28.1 dB | **+1.5 dB** |

**平均改善：+1.7 dB**

### Tanks & Templesデータセット

| シーン | 3DGS | 2DGS | 改善 |
|--------|------|------|------|
| Truck | 25.8 dB | 28.3 dB | **+2.5 dB** |
| Train | 21.7 dB | 24.1 dB | **+2.4 dB** |
| Playground | 26.1 dB | 27.8 dB | **+1.7 dB** |

**平均改善：+2.2 dB**

### なぜ2DGSの方が高いのか

改善の主な理由：

1. **奥行きブラーの排除**：厚みゼロのディスクはシャープな境界を生成
2. **サーフェスへの密着**：ディスクが表面に沿って配置されるため、テクスチャ詳細が保存される
3. **オーバーラップの削減**：3DGSでは複数の楕円体が無駄に重なるが、2DGSは必要最小限

特に**屋外シーン**（Garden, Bicycle）や**複雑な幾何学**（Truck, Train）で改善が顕著。

## サーフェス品質：メッシュ抽出の決定的差

2DGSの真価は**メッシュ抽出**で発揮される。

### 3DGSのメッシュ抽出問題

3DGSからメッシュを抽出する方法：

1. **Poisson Reconstruction**：楕円体の中心から法線を推定→ノイジー
2. **Marching Cubes**：密度フィールドを構築→ぼやけた境界
3. **TSDF Fusion**：深度マップから統合→3DGS自体が深度を持たない

いずれの方法も**品質が低い**。理由：

- 楕円体は「ぼんやりした塊」なので、シャープなサーフェスを表現できない
- 法線が不正確（楕円体の主軸から推定するが、複数の楕円が重なると破綻）
- エッジ部分で楕円体が浮いているため、穴が開きやすい

### 2DGSのメッシュ抽出利点

2DGSでは：

1. **明示的な法線**：各ディスクが正確な法線を持つ
2. **厚みゼロ**：サーフェスに密着しているため、境界が正確
3. **Poisson Reconstructionが自然**：法線ベクトルをそのまま使える

結果として：

- **エッジがシャープ**
- **穴が少ない**
- **テクスチャ詳細が保存される**

### 比較図（概念）

```
3DGS → Mesh:
  ●  ●  ●  ●  ●     →  ／￣￣＼   (ノイジー、ぼやけた境界)
   ●  ●  ●  ●      →  ｜ ・ ・ ｜
  ●  ●  ●  ●  ●     →  ＼＿＿／

2DGS → Mesh:
  │ │ │ │ │       →  ／￣￣＼   (シャープ、正確な境界)
  │ │ │ │ │       →  ｜  ･ ･ ｜
  │ │ │ │ │       →  ＼＿＿／
```

### リライティング対応

2DGSは法線を持つため、**PBR（Physically Based Rendering）** を適用できる：

- 法線マッピング
- Specular reflection
- 環境光遮蔽（AO）

3DGSでは、これらを後付けで実装するのは困難（法線推定の精度不足）。

## 弱点：ボリューメトリック表現の喪失

2DGSは万能ではない。**厚みゼロ**という特性が致命的弱点になる場合がある。

### 2DGSが苦手なシーン

| シーン種類 | 3DGS | 2DGS | 理由 |
|-----------|------|------|------|
| 煙・霧 | ✅ 得意 | ❌ 不可能 | 厚みがないと体積効果を表現できない |
| ガラス | ✅ そこそこ | ❌ 困難 | 屈折・反射は厚みが必要 |
| 半透明物体 | ✅ 自然 | ❌ 困難 | 厚み方向の半透明グラデーション不可 |
| 毛髪 | ✅ まあまあ | ❌ 困難 | 細かい体積的構造が必要 |
| 固体サーフェス | ✅ 普通 | ✅ 優秀 | 2DGSが有利 |

### 具体例：煙のシーン

**3DGS**：
```
カメラ → ●●●●● ← 楕円体が重なって密度グラデーション
         ↑
    奥に行くほど薄くなる → 自然な煙
```

**2DGS**：
```
カメラ → │ │ │ ← ディスクが並ぶだけ
         ↑
    厚みがない → 煙に見えない（薄い板の集合）
```

### ガラスの問題

ガラスは**厚み方向の屈折**が重要だが、2DGSのディスクは厚みゼロなので：

- 屈折角を計算できない
- 内部散乱を表現できない
- 複数層のガラス（窓ガラス越しに別の窓）は破綻

### 対処法：ハイブリッドアプローチ

一部の研究では**3DGS + 2DGSのハイブリッド**が提案されている：

- **2DGS**：固体サーフェス（壁、床、家具）
- **3DGS**：ボリューメトリック効果（煙、霧、髪）

シーン解析で領域を分離し、適切な表現を選択する。これは2026年の研究トレンドの1つ。

## 実装難易度：ラスタライザーの全面書き直し

筆者の視点で、2DGS実装の難易度を評価する。

### 3DGS→2DGS移行で変更が必要な箇所

| モジュール | 変更規模 | 理由 |
|-----------|---------|------|
| **Forward rasterizer** | 全面書き直し | 投影→レイ-ディスク交差に変更 |
| **Backward rasterizer** | 全面書き直し | 勾配計算がレイベースに |
| **Densification** | 大幅変更 | 法線一貫性を考慮した分裂ロジック |
| **Pruning** | 小変更 | 基本ロジックは同じ |
| **SH計算** | 変更なし | 視点依存色は同じ |
| **最適化** | 再実装 | FP16、SoA等をゼロから |

### Forward rasterizer の書き直し内容

**3DGS（投影ベース）**：
```
1. 3D楕円体を2Dに投影
2. スクリーン上の楕円を描画（Gaussianカーネル）
3. タイルごとにソート
4. アルファブレンディング
```

**2DGS（レイベース）**：
```
1. ピクセルごとにレイを生成
2. 各ディスクとの交差判定
   - レイとディスクの平面方程式を解く
   - 交差点が円内かチェック
3. 交差したディスクをソート
4. アルファブレンディング
```

**実装量**：約2000〜3000行のCUDAコードを書き直し

### Backward rasterizer の複雑さ

勾配計算が特に複雑：

- **3DGS**：2D投影の微分（解析的に計算可能）
- **2DGS**：レイ-ディスク交差の微分（陰関数微分が必要）

特に、以下のパラメータの勾配が難しい：

- **法線ベクトルの勾配**：単位ベクトル制約下での微分
- **ディスク半径の勾配**：交差判定の境界での不連続性
- **位置の勾配**：レイ方向と法線の相互作用

**実装量**：約1500〜2500行のCUDAコード

### 既存最適化の再実装

筆者がHyperRasterizerで実装した最適化：

| 最適化 | 実装難易度 | 2DGSでの再現性 |
|--------|----------|-------------|
| FP16演算 | 高 | 全面的に再設計が必要 |
| SoA（Structure of Arrays） | 中 | メモリレイアウト全変更 |
| Debug code除去 | 低 | 同じ |
| thread_local修正 | 低 | 同じ |
| Shared memory最適化 | 高 | レイ計算に合わせて再設計 |

**推定工数**：3〜6ヶ月（フルタイムの場合）

### エコシステム互換性の問題

2DGSに移行すると、以下の問題が発生：

1. **ビューアの非互換**：既存の3DGSビューアは2DGSを表示できない
2. **.plyフォーマット変更**：法線ベクトルを追加する必要
3. **エディタツール**：3DGS用のGaussian編集ツールが使えない
4. **コミュニティリソース**：3DGSの豊富なノウハウが流用できない

2026年時点では、**2DGSのエコシステムは未成熟**。

## コスパ分析：PSNR改善の代替手段

ここで重要な問いがある：「**PSNR改善だけが目的なら、2DGSは最適解か？**」

### Appearance Embeddingの威力

**Appearance Embedding**は、各訓練画像に対して小さな潜在ベクトル（16〜32次元）を追加する手法。

**効果**：
- **+1〜2 dB PSNR**（データセットによる）
- **実装量**：60〜100行のPythonコード
- **訓練時間増加**：+5〜10%
- **既存ラスタライザー変更**：不要（または最小限）

### コスパ比較表

| 手法 | PSNR改善 | 実装工数 | 訓練時間 | エコシステム互換性 |
|------|---------|---------|---------|----------------|
| **2DGS** | +1〜3 dB | 3〜6ヶ月 | +20〜30% | ❌ 非互換 |
| **Appearance Emb.** | +1〜2 dB | 1〜3日 | +5〜10% | ✅ 完全互換 |
| **Anti-aliasing (Mip-Splatting)** | +0.5〜1 dB | 2〜4週間 | +10〜15% | ✅ ほぼ互換 |
| **Depth regularization** | +0.3〜0.8 dB | 1週間 | +5% | ✅ 完全互換 |

### 筆者の判断基準

**PSNR改善だけが目的の場合**：
1. まずAppearance Embedding（コスパ最高）
2. 次にAnti-aliasing（Mip-Splatting等）
3. Depth regularization
4. それでも不足なら2DGS検討

**2DGSを選ぶべき場合**：
- メッシュ抽出品質が重要
- リライティング/PBRが必要
- CADデータ生成が目的
- 固体サーフェスのみのシーン

**2DGSを避けるべき場合**：
- ボリューメトリック効果が必要
- 実装工数が取れない
- エコシステム互換性が重要
- 既存の3DGS最適化を活用したい

## どちらを選ぶべきか：ユースケース別判断

実際のプロジェクトでの判断マトリクスを示す。

### シーン特性による判断

| シーン種類 | 推奨 | 理由 |
|-----------|------|------|
| **建築物（屋内）** | 2DGS | サーフェス品質が重要、ボリューメトリック不要 |
| **建築物（屋外）** | 2DGS | 同上、メッシュ抽出で建物モデル化 |
| **自然風景** | 3DGS | 植物、霧、複雑な半透明要素 |
| **人物** | 3DGS | 髪、服の透け感、微細な体積表現 |
| **製品撮影** | 2DGS | 固体サーフェス、リライティング対応 |
| **文化財** | 2DGS | 高精度メッシュ、CADデータ化 |
| **VFX（映画）** | 3DGS | 煙、爆発、半透明エフェクト |
| **AR/VR** | 2DGS | リアルタイムリライティング |

### 目的による判断

| 目的 | 推奨 | 理由 |
|------|------|------|
| **高PSNR（表示品質）** | まず3DGS+Appearance Emb. | コスパが良い |
| **メッシュ抽出** | 2DGS | 圧倒的に高品質 |
| **リライティング** | 2DGS | 法線が必須 |
| **リアルタイムレンダリング** | 3DGS | ラスタライザーが高速 |
| **学習速度** | 3DGS | 訓練が安定・高速 |
| **新規研究** | 2DGS | フロンティア領域 |

### 技術リソースによる判断

| 条件 | 推奨 | 理由 |
|------|------|------|
| CUDA実装経験が豊富 | 2DGS可 | 実装難易度に耐えられる |
| 既存3DGS実装あり | 3DGS | 資産活用 |
| 実装工数 < 1週間 | 3DGS | 2DGSは時間不足 |
| 研究プロジェクト（長期） | 2DGS可 | 投資価値あり |
| 商用プロダクト（短期） | 3DGS | エコシステム安定性 |

## 2026年の動向：ハイブリッドと統合

2026年時点での研究トレンドを紹介する。

### ハイブリッドアプローチ（3DGS + 2DGS）

複数の研究グループが**自動領域分割**を提案：

1. **シーン解析**：セグメンテーションでサーフェス/ボリューム領域を分離
2. **適応的表現**：
   - サーフェス → 2DGS
   - ボリューム → 3DGS
3. **統合レンダリング**：両方を同一パイプラインで処理

**利点**：
- 両方の長所を活用
- PSNRとボリューメトリック品質の両立

**課題**：
- セグメンテーション精度
- 境界での不連続性
- 実装複雑度の増加

### GOF（Gaussian Opacity Fields）

2DGSの派生手法で、**不透明度フィールド**を導入：

- ディスクの厚み方向に薄い不透明度分布を持たせる
- 完全な厚みゼロではなく、「ほぼゼロ」
- ボリューメトリック効果を限定的にサポート

**結果**：2DGSと3DGSの中間的性質

### Neural Gaussians

Gaussian表現に**ニューラルネットワーク**を統合：

- 各Gaussianが小さなMLPを持つ
- 視点依存効果を高精度に表現
- SH係数より表現力が高い

2DGS/3DGSの両方に適用可能。

### Relightable 3DGS/2DGS

リライティング特化の拡張：

- **BRDF分解**：Diffuse/Specular/Roughnessを明示的に学習
- **環境光推定**：訓練画像から照明を逆推定
- **任意照明下でレンダリング**

2DGSは法線を持つため、この方向で有利。

### 商用ツールの動向

| ツール/企業 | 対応状況 | 備考 |
|-----------|---------|------|
| Luma AI | 3DGS中心 | 2DGSは実験的サポート |
| Polycam | 3DGS | 2DGS未対応 |
| Gaussian Splatting Viewer (WebGPU) | 3DGS | コミュニティベース |
| SuperSplat (PlayCanvas) | 3DGS | 2DGS未定 |

**結論**：2026年2月時点で、商用エコシステムは**3DGS優位**。2DGSは研究段階。

最終的な選択をフローチャートで示す。

```
START
  │
  ▼

  │
  ├─ YES → [リライティングも必要？]
  │           │
  │           ├─ YES → 【2DGS】
  │           └─ NO  → [シーンにボリューメトリック要素あり？]
  │                      │
  │                      ├─ YES → [ハイブリッド検討] or 【3DGS】
  │                      └─ NO  → 【2DGS】
  │
  └─ NO → [ボリューメトリック効果が重要？]
            │
            ├─ YES → 【3DGS】
            └─ NO  → [実装工数は十分？（3ヶ月以上）]
                       │
                       ├─ YES → [PSNR改善幅が+2dB以上必要？]
                       │          │
                       │          ├─ YES → 【2DGS】
                       │          └─ NO  → 【3DGS + Appearance Emb.】
                       │
                       └─ NO  → 【3DGS】
```

### 簡易判定表

**2DGSを選ぶべき明確なケース**：
- CADデータ生成プロジェクト
- 建築物の3Dモデル化
- ARアプリでのリライティング
- 文化財デジタルアーカイブ

**3DGSを選ぶべき明確なケース**：
- VFX制作（煙、爆発）
- 自然風景の高品質再現
- 人物の全身3D化
- 既存の3DGS実装がある

**どちらでも良いケース**：
- 一般的な物体撮影 → まず3DGS（実装容易）、必要なら2DGS

## まとめ：実装者が知っておくべきこと

### 3DGS vs 2DGSの本質的違い

| 観点 | 3DGS | 2DGS |
|------|------|------|
| 表現 | 3D楕円体（厚みあり） | 2Dディスク（厚みゼロ） |
| レンダリング | 投影ベース | レイベース |
| PSNR | 標準 | +1〜3 dB |
| サーフェス品質 | 低い | 高い |
| ボリューメトリック | 得意 | 不可能 |
| メッシュ抽出 | 低品質 | 高品質 |
| 実装難易度 | 中 | 高 |
| エコシステム | 成熟 | 発展途上 |

### 筆者の経験からの教訓

1. **PSNRだけならAppearance Embeddingが最強コスパ**
   - 60行のコードで+1〜2 dB
   - 2DGS移行の前に試すべき

2. **2DGSはメッシュ抽出目的でこそ真価**
   - 表示品質だけなら3DGSで十分なケースが多い
   - CAD化、リライティングが必要なら2DGS一択

3. **ボリューメトリック要素を見逃すな**
   - 植物、髪、霧、ガラスがあるなら3DGS
   - 固体サーフェスのみなら2DGS有利

4. **実装工数は想定の2倍以上**
   - ラスタライザー書き直しは大工事
   - デバッグ時間を甘く見てはいけない

5. **エコシステムの重要性**
   - ビューア、エディタ、コミュニティリソース
   - 2026年時点では3DGSが圧倒的

### 2026年の推奨戦略

**短期プロジェクト（〜3ヶ月）**：
- 3DGS + Appearance Embedding
- 必要なら追加でMip-Splatting

**中期プロジェクト（3〜12ヶ月）**：
- 用途明確なら2DGS投資OK
- メッシュ抽出・リライティング目的なら特に

**長期研究（12ヶ月〜）**：
- ハイブリッドアプローチ検討
- Neural Gaussians等の最新手法も視野

### 最後に

2D Gaussian Splattingは魅力的な技術だが、「3DGSの完全な上位互換」ではない。**適材適所**が重要だ。

筆者自身、HyperRasterizerでの最適化を重ねてきた経験から、2DGS移行は「必要性が明確な場合のみ」と判断している。多くのケースで、**3DGS + 軽量な拡張**（Appearance Embedding等）の方がコスパに優れる。

しかし、メッシュ抽出やリライティングが必要なプロジェクトでは、2DGSは強力な選択肢だ。自分のプロジェクトの要件を整理し、上記のフローチャートを参考に判断してほしい。
