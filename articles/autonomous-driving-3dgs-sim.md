# 結論から言う

**3D Gaussian Splatting（3DGS）を使えば、実際の道路環境を写実的に再現したシミュレーション環境を構築でき、自動運転のテスト走行コストを1/100以下に削減できる。**

従来のゲームエンジンベースのシミュレーションでは「見た目はリアルだがセンサー応答が現実と異なる」という根本的な問題があった。3DGSは実写データから直接3D空間を再構成するため、カメラ・LiDARの応答が現実と一致する。

これは自動運転開発のゲームチェンジャーだ。

---

# 3DGSとは（30秒で理解）

3D Gaussian Splattingは、複数視点の写真から3D空間を再構成する技術だ。

```
入力: 複数視点の画像（数十〜数百枚）
  ↓
処理: 3D Gaussianの最適化（数分〜数十分）
  ↓
出力: リアルタイムレンダリング可能な3Dシーン
```

**NeRFとの最大の違いはレンダリング速度。** NeRFが1フレーム数秒かかるのに対し、3DGSは100FPS以上でレンダリングできる。自動運転シミュレーションに求められるリアルタイム性を満たす唯一の実写ベース手法と言っていい。

# 自動運転での活用シーン

## 1. 走行シミュレーション環境の構築

最も直接的な活用。走行済みルートのカメラ映像から3DGS空間を構築し、任意の視点から再レンダリングする。

**Street Gaussians**（ECCV 2024）は、動的な車両と静的な背景を分離して再構成する手法を提案した。これにより、他車の位置や速度を自由に変更したシナリオを生成できる。

```
実走行データ → 静的背景3DGS + 動的オブジェクト3DGS
                     ↓
          任意のシナリオを合成（車両配置変更、天候変更等）
                     ↓
          自動運転モデルの評価・テスト
```

## 2. LiDAR + カメラのセンサーフュージョン

3DGSはRGBだけでなく、**深度情報やLiDAR点群との統合**が可能だ。GaussianFormerのようなアプローチでは、3D Gaussianを使って3D占有予測（Occupancy Prediction）を行い、LiDARとカメラの情報を統合的に扱う。

シミュレーション環境でセンサーフュージョンのアルゴリズムを検証できることは、実車テストの大幅な削減につながる。

## 3. コーナーケースのシナリオ生成

自動運転で最も難しいのは**レアケースへの対応**だ。飛び出し、逆光、豪雨など、実走行で遭遇する確率が低いシナリオを意図的に生成する必要がある。

3DGS環境では以下の操作が可能：

- **照明条件の変更**: 時間帯、天候のシミュレーション
- **オブジェクト挿入**: 歩行者、自転車、障害物の配置
- **視界遮蔽**: 大型車両による死角シナリオ
- **路面状況**: 濡れた路面の反射特性再現

## 4. 高精度地図（HDマップ）の3D化

HDマップは自動運転に不可欠だが、**更新コストが膨大**だ。3DGSを使えば、走行映像からHDマップを自動的に3D化し、変化点を検出できる。

道路工事、新しい標識、車線変更といった変化を、再走行データと既存3DGSモデルの差分で自動検出する研究が進んでいる。

# 最新研究

| 研究名 | 年 | 概要 | 特徴 |
|--------|-----|------|------|
| **Street Gaussians** | ECCV 2024 | 動的街路シーンの再構成 | 動的/静的分離、追跡統合 |
| **DrivingGaussian** | 2024 | 大規模走行シーン再構成 | マルチカメラ、LiDAR統合 |

**注目すべきはStreet Gaussians。** 動的オブジェクトを個別の4D Gaussianとしてモデル化し、追跡情報と組み合わせることで、車両の軌跡を自由に編集できる。自動運転シミュレーションに最も直結する研究だ。

# 従来手法との比較

| 項目 | ゲームエンジン | NeRFベース | **3DGSベース** |
|------|--------------|-----------|---------------|
| 視覚品質 | 高（手動制作） | 高（実写ベース） | **高（実写ベース）** |
| レンダリング速度 | 60+ FPS | 0.1-1 FPS | **100+ FPS** |
| センサー忠実度 | 低 | 高 | **高** |
| シーン構築コスト | 非常に高い | 中 | **低** |
| 動的オブジェクト | 容易 | 困難 | **研究段階** |
| スケーラビリティ | 高 | 低 | **中〜高** |
| 初期投資 | 数千万円 | 数百万円 | **数十万円** |

**3DGSの圧倒的な優位点は「実写ベース×リアルタイム」の両立。** ゲームエンジンは見た目のリアリティは高いが、実際のセンサー応答とは乖離がある。NeRFは実写ベースだがリアルタイム性がない。3DGSだけが両方を満たす。

# 技術的課題

3DGSの自動運転応用にはまだ解決すべき課題がある。

## 動的オブジェクトの扱い

3DGSは本質的に静的シーンの再構成手法だ。Street Gaussiansのように動的オブジェクトを分離する研究が進んでいるが、**歩行者の自然な動き**や**予測不能な行動**の生成はまだ難しい。

## 大規模シーンの効率的な表現

都市規模のシーン（数km〜数十km）を単一の3DGSで表現するのは、メモリと計算コストの面で現実的ではない。**LoD（Level of Detail）管理**やストリーミング技術が必要だ。

## リアルタイムでの物理シミュレーション統合

レンダリングは高速だが、**衝突判定やタイヤの物理モデル**との統合はまだ研究段階だ。3DGSの幾何情報から物理シミュレーション用のメッシュを自動生成するアプローチが有望視されている。
