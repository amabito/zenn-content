# 結論から言う

**3DGS学習の品質は、カーネルやアルゴリズムより「入力データの品質」と「パラメータチューニング」で決まる。** 学習フレームワークを10回以上作り直し、V1からV22まで改良を重ねた実体験から、品質を上げるための実践チェックリスト30項目をまとめた。

PSNRが思ったより上がらない、floaterが消えない、ぼやける。これらの問題の8割は、このチェックリストのどこかに原因がある。

**この記事で得られること:**
- 入力画像からSfM、学習パラメータ、評価まで網羅したチェックリスト
- よくある失敗パターンと対処法
- 各チェック項目の重要度と確認方法

**対象読者:**
- 3DGS学習を始めたが品質が出ない人
- gsplat/nerfstudioを使っているが、パラメータの意味がわからない人
- 自作フレームワークで品質向上を目指す人

# 入力画像の品質（チェック項目1-8）

入力画像の品質が3DGS学習の上限を決める。どんなに優れたアルゴリズムでも、入力が悪ければ品質は出ない。

## 1. 解像度は十分か

```
推奨解像度:
├── 屋内シーン: 1920x1080以上
├── 屋外シーン: 2560x1440以上
├── 細部再現が必要: 3840x2160以上
└── 学習時はダウンスケールしてもよい（x0.5, x0.25）
```

**注意:** 高解像度=高品質ではない。ブレた4Kよりシャープな1080pのほうが品質は高い。

## 2. モーションブラーはないか

```
確認方法:
├── 画像をピクセル等倍で確認
├── エッジ部分がシャープか
├── テキストや細い線が読めるか
└── ツール: 目視 or Laplacian分散値でスクリーニング
```

**Laplacian分散値の目安:**
- 100以上: シャープ
- 50-100: 許容範囲
- 50未満: ブレあり、除外推奨

## 3. 露出は一貫しているか

```
確認方法:
├── 同一面を写す複数画像の明るさを比較
├── ヒストグラムの分布が画像間で大きく異なっていないか
├── オート露出による変動がないか
└── 対策: 手動露出固定、またはフォトメトリック補正
```

**重要度: 高。** マルチカメラの場合は特に重要。ExposureMLP等の補正を検討すること。

## 4. ホワイトバランスは統一されているか

```
確認方法:
├── 白い壁や紙が同じ色に写っているか
├── カメラ間で暖色/寒色の偏りがないか
└── 対策: RAW撮影 + 統一現像、またはフォトメトリック補正
```

## 5. カバレッジは十分か

```
チェックポイント:
├── 再構成したい領域が3方向以上から撮影されているか
├── 死角（一方向からしか見えない領域）がないか
├── テクスチャレスな領域（白壁等）に十分な視点があるか
└── 目安: 1m四方あたり最低5-10枚
```

**よくある失敗:** 天井・床の撮影忘れ。ウォークスルーだけでは天井のカバレッジが不足する。

## 6. 画像間のオーバーラップは十分か

```
推奨:
├── 隣接画像のオーバーラップ: 60-80%
├── 動画の場合: 1-2秒間隔で抽出（30fps撮影で15-60枚/秒は過剰）
└── 少なすぎ: SfMが失敗する
    多すぎ: 学習時間が増大するだけで品質は頭打ち
```

## 7. 動体は除外されているか

```
問題となるケース:
├── 人物が歩いている
├── 車が通過する
├── 風で揺れる植物
└── 対策: マスク（SAMなど）で動体を除外
```

## 8. レンズ歪みは補正済みか

```
確認方法:
├── 直線が曲がっていないか（特に画像端）
├── COLMAPがundistort画像を出力しているか
├── 魚眼レンズの場合は専用モデルを使用
└── 対策: OpenCV undistort or COLMAP built-in
```

# SfM / COLMAP（チェック項目9-14）

SfMの品質が3DGS学習の起点。ここが壊れると後の工程で挽回できない。

## 9. 特徴点数は十分か

```
COLMAPログの確認ポイント:
├── Total features extracted: 画像あたり3000以上が目安
├── 特徴点が少ない → テクスチャレスな領域が多い
└── 対策: SIFTパラメータ調整、max_num_features増加
```

## 10. マッチング成功率は高いか

```
確認方法:
├── COLMAPのmatching statsを確認
├── 成功率80%以上が目安
├── 低い場合 → オーバーラップ不足 or 露出差
└── 対策: exhaustive matching、またはvocab tree matching
```

## 11. 再構成された画像数は入力数と一致するか

```
確認方法:
├── registered images / total images を確認
├── 90%以上が登録されているべき
├── 脱落した画像 → ブレ、露出異常、視点が離れすぎ
└── 対策: 脱落画像を確認し、原因を特定
```

**よくある失敗:** 100枚入力して60枚しか登録されない。原因は撮影間隔が広すぎるケース。

## 12. 再投影誤差は小さいか

```
目安:
├── 平均再投影誤差: 0.5 pixel以下が理想
├── 1.0 pixel以上 → カメラモデルの問題
├── 2.0 pixel以上 → データに重大な問題あり
└── 確認: COLMAPのsparse reconstruction summary
```

## 13. 点群の密度は適切か

```
確認方法:
├── sparse点群をCloudCompare等で可視化
├── シーンの主要構造が認識できるか
├── 点群が偏っていないか（特定領域に集中）
├── 目安: 屋内シーンで10万-100万点
└── dense点群は不要（3DGSは自分でdensifyする）
```

## 14. 座標系の正規化は適切か

```
重要ポイント:
├── シーンの中心が原点付近にあるか
├── スケールが適切か（単位がメートル程度）
├── バウンディングボックスが妥当か
└── 対策: nerfstudio形式のtransform.jsonで正規化
```

**注意:** 座標系がずれていると、learning rateの設定が全く合わなくなる。

# 学習パラメータ（チェック項目15-22）

## 15. Learning Rateは適切か

```
一般的な設定:
├── position lr: 1.6e-4（初期）→ 1.6e-6（最終）
├── opacity lr: 0.05
├── scaling lr: 5e-3
├── rotation lr: 1e-3
├── SH lr: 2.5e-3（DC）/ 1.25e-4（高次）
└── exponential decayで段階的に減衰
```

**よくある失敗:**
- Position lrが高すぎ → Gaussianが暴走・振動
- Opacity lrが低すぎ → 不要なGaussianが消えない

## 16. Densification閾値は調整されているか

```
確認ポイント:
├── 勾配閾値（grad_threshold）: 通常 2e-4
├── 高すぎ → densifyされない → ぼやける
├── 低すぎ → Gaussianが爆発的に増加 → メモリ不足
└── シーンの複雑さに応じて調整
```

## 17. Densification開始・終了タイミングは適切か

```
一般的な設定:
├── 開始: 500 iteration
├── 終了: 15000 iteration
├── 間隔: 100 iterationごと
└── 初期は高頻度、後半は安定化に集中
```

**注意:** 終了が早すぎると細部が再現されない。遅すぎると不安定なGaussianが増える。

## 18. Clone vs Split比率は適切か

```
densificationの2つの操作:
├── Clone: 小さいGaussianを複製（詳細を増やす）
├── Split: 大きいGaussianを分割（構造を細分化）
└── 一般的な判定: scale > threshold → split, else → clone
```

## 19. Pruning条件は適切か

```
確認ポイント:
├── opacity < 0.005 のGaussianを削除
├── 巨大なGaussian（world-space scaleが大きすぎる）を削除
├── screen-space sizeが大きすぎるGaussianを削除
├── pruning頻度: densificationと同じ間隔
└── pruningが弱い → メモリ無駄遣い、速度低下
```

## 20. Opacity Resetは設定されているか

```
効果:
├── 全Gaussianのopacityを低い値にリセット
├── 不要なGaussianが次のpruningで削除される
├── タイミング: 3000 iteration付近（1回のみ）
├── リセット値: 0.01
└── 効果: floater削減、メモリ効率改善
```

**重要度: 高。** Opacity Resetなしだと不要なGaussianが蓄積し、品質・速度の両方が劣化する。

## 21. Scale制約は設定されているか

```
問題: Gaussianのscaleが制御不能に大きくなる
対策:
├── max_scale制約: world-space scaleの上限を設定
├── scale regularization: L1/L2正則化でscaleを抑制
└── 効果: 針状Gaussianの抑制、安定した学習
```

## 22. 総iteration数は十分か

```
目安:
├── 最低: 7,000 iteration
├── 推奨: 30,000 iteration
├── 高品質: 50,000-100,000 iteration
├── 収束判定: loss plateauの確認
└── 長すぎても効果は頭打ち（30k以降は改善幅小）
```

# 評価とデバッグ（チェック項目23-30）

## 23. PSNR/SSIM/LPIPSを測定しているか

```
指標と目安:
├── PSNR: 30 dB以上が良好、25 dB以下は要改善
├── SSIM: 0.90以上が良好
├── LPIPS: 0.10以下が良好
└── 3指標全てを見ること（PSNRだけでは不十分）
```

**なぜ3指標必要か:**
- PSNR: ピクセル単位の誤差 → ぼけに敏感だがアーティファクトに鈍感
- SSIM: 構造的類似度 → 人間の知覚に近い
- LPIPS: 学習ベースの知覚指標 → テクスチャの自然さを評価

## 24. Train/Test分割は適切か

```
推奨:
├── テスト画像: 全体の10%（等間隔で選択）
├── テスト画像は学習に使わない
├── 同一視点の画像がtrain/testに分かれないこと
└── テスト画像でのメトリクスが本来の品質
```

**よくある失敗:** テスト画像なしで学習画像のPSNRだけ見る → 過学習に気づかない。

## 25. Visual Artifactを目視確認しているか

```
確認すべきアーティファクト:
├── floater: 空中に浮遊する半透明の塊
├── 針状Gaussian: 細長い線状のアーティファクト
├── ぼけ: テクスチャが不鮮明
├── 色むら: 領域間の色の不連続
├── 穴: 点群が不足して背景が見える
└── ゴースト: 動体が半透明に残る
```

**メトリクスが良くても目視で問題がある場合は多い。** PSNR 30 dBでもfloaterがあれば品質として不十分。

## 26. Gaussian数は適切か

```
目安:
├── 屋内小シーン: 50万-200万
├── 屋内中シーン: 200万-500万
├── 屋外大シーン: 500万-2000万
├── 多すぎ → メモリ不足、推論速度低下
└── 少なすぎ → 細部が再現されない
```

## 27. 学習曲線を監視しているか

```
確認ポイント:
├── lossが単調減少しているか
├── 急激なスパイクがないか
├── plateau（横ばい）の位置
├── train lossとtest lossの乖離（過学習の兆候）
└── ツール: TensorBoard, wandb
```

**スパイクの原因:**
- Densification直後 → 正常（新しいGaussian追加直後は一時的に悪化）
- Opacity Reset直後 → 正常（リセット後に回復）
- ランダムなスパイク → learning rateが高すぎる可能性

## 28. SH（Spherical Harmonics）次数は適切か

```
設定:
├── SH 0次（DC成分のみ）: 色が均一、ビュー依存なし
├── SH 1次: 基本的なビュー依存性
├── SH 2次: 十分なビュー依存性（推奨）
├── SH 3次: 高品質だがメモリ増大
└── 高次SHは後半から有効化する設計が安定
```

## 29. Background Colorは適切か

```
設定:
├── 黒背景 (0,0,0): 屋内シーン向け
├── 白背景 (1,1,1): 物体単体のキャプチャ向け
├── ランダム背景: 学習時に背景色を毎回ランダム化
│   → opacity学習が安定する（推奨）
└── 背景色の不一致 → opacity学習が壊れる原因
```

## 30. 再現性は確保されているか

```
チェックポイント:
├── random seedを固定しているか
├── 同じデータ・同じパラメータで同じ結果が出るか
├── 設定ファイル（yaml/json）を保存しているか
├── 学習済みモデル（.ply）を保存しているか
└── 途中経過のチェックポイントを保存しているか
```

**重要:** パラメータを変更して比較実験する際、再現性がないと改善・劣化の判断ができない。

# よくある失敗パターンと対処法

## パターン1: PSNRが25 dBから上がらない

```
原因（可能性順）:
1. 入力画像の品質問題（ブレ、露出差）
2. SfMの再投影誤差が大きい
3. フォトメトリック補正未実施
4. Densification閾値が高すぎる

対処:
1. Laplacian分散でブレ画像を除外
2. COLMAPを再実行（パラメータ調整）
3. ExposureMLPを有効化
4. grad_thresholdを下げる
```

## パターン2: floaterが大量発生

```
原因（可能性順）:
1. フォトメトリック不一致
2. 動体が入力に含まれている
3. Opacity Resetが未設定
4. Pruningが弱い

対処:
1. 露出補正を適用
2. SAM等でマスク処理
3. Opacity Reset追加（3000 iter付近）
4. opacity/scale pruning閾値を調整
```

## パターン3: 学習中にGaussian数が爆発

```
原因（可能性順）:
1. Densification閾値が低すぎる
2. Pruningが無効or弱い
3. 入力画像のノイズ
4. Scale制約がない

対処:
1. grad_thresholdを上げる
2. pruning条件を追加・強化
3. ノイズ除去前処理
4. max_scale制約を追加
```

## パターン4: 特定の領域だけぼやける

```
原因（可能性順）:
1. その領域の撮影枚数が不足
2. テクスチャレスな面（白壁等）
3. Densificationが届いていない
4. SfMでその領域の点群が疎

対処:
1. 追加撮影
2. 近距離からの撮影を追加
3. Densificationを延長
4. COLMAPのdense reconstructionで初期点群を増やす
```

# まとめ

| カテゴリ | 項目数 | 重要度 |
|---------|--------|--------|
| 入力画像 | 8項目 | 最高（ここが品質上限） |
| SfM/COLMAP | 6項目 | 高（基盤） |
| 学習パラメータ | 8項目 | 高（チューニング） |
| 評価・デバッグ | 8項目 | 中（検証） |

**品質改善の優先順位:**
1. まず入力画像の品質を確認（項目1-8）
2. 次にSfMの品質を確認（項目9-14）
3. その上で学習パラメータを調整（項目15-22）
4. 評価指標と目視で検証（項目23-30）

上流の問題を下流で解決しようとしても効果は限定的。**入力データの品質が全ての起点。**
